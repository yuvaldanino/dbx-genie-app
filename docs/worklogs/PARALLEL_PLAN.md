8. **Dependencies are frozen.** This machine blocks PyPI and npm via /etc/hosts. NEVER run `bun install <new-pkg>`, `uv add`, or `pip install`. Work with what's installed. If a feature truly needs a new dependency: STOP and ask the user.

# Session B brief — P0 #3: Embedded "Genie Chat" mode

## Mission

A continuous, ChatGPT-style conversation view per space — the native-Genie feel — alongside the existing Query Workspace. User decision: **not persisted** (each visit starts a fresh thread); **no backend changes needed** — `POST /api/chat/start` already accepts `conversation_id` (continuation) and `ephemeral: true` (skip persistence).

## UX spec

- New sidebar nav item **"Genie Chat"** (icon suggestion: `MessageSquare` or `Sparkles` from lucide) in `_sidebar/route.tsx`, routing to `/genie-chat?spaceId=...` — same spaceId search-param pattern as `chat.tsx`.
- Layout: scrolling message thread (user question right/accent, Genie response left/card), sticky input bar at the bottom (Enter to send, Shift+Enter newline), auto-scroll on new content.
- Each Genie response renders: markdown description (`md-components`), chart (`ChartRenderer` via `chart_suggestion`) when ≥2 cols + data, table (`DataTable`), collapsible SQL — reuse existing components; if `MessageBubble.tsx` fits, use it; if not, build your own bubbles in `components/apx/genie-chat/` (do NOT modify MessageBubble).
- **Conversation continuity is the whole point**: keep ONE `conversation_id` for the session — `useChatFlow({ spaceId, ephemeral: true })` already does this (verify in network tab: the 2nd+ message must POST the same `conversation_id`).
- **"New chat" button** (top of thread): resets to a fresh conversation (re-mount the hook or reset its state — your call, document it).
- **Suggested follow-ups**: render `response.suggested_questions` as clickable chips under each response → clicking sends it. Show the space's `config.sample_questions` as starter chips on the empty thread.
- Status while waiting: reuse the hook's `statusText` progression (Submitting… → Generating SQL… → Running query…); show a typing-indicator-style bubble.
- Branding: space colors/logo from `config` like other pages. Works in dark mode. Handle `is_clarification` responses (Genie asking back) as plain text bubbles without data sections.
- Errors: friendly inline bubble (no blank screens, no stuck spinners) — `response.error` already carries the message.

# If things go wrong

- **Merge conflict anyway** → A resolves at integration; B's PR is never force-updated.
- **B blocked >30 min on anything** (tooling, ambiguous spec, read-only file needed) → write worklog entry, tell the user, wait. Do not improvise outside the contract.
- **Live app broken during parallel phase** → that's A's domain (only A deploys). B continues against the last-good deploy; if the proxy errors, B reports and pauses live testing.
- **Abort parallelism** → B simply stops committing; its branch keeps. A continues alone. Nothing else to unwind.
